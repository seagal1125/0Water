# AI Agent 思考與執行過程紀錄

這份文件紀錄了 AI Agent 如何處理「漏水爭議文件整理」任務的完整思考邏輯與執行步驟，供教育訓練使用。

## 1. 使用者需求 (User Prompt)

**原始指令：**
> 「把漏水爭議內容重新排版 好釐清這個事件的進度 這裡面還有一個判決 待會我會再寫程式抓更多的判決 一個判決會對應一個摘要 我要清楚看出判決跟防水層有關的觀點 所以判決的部分你要另外存一個資料結構或是檔案 用你覺得適合的方式儲存」

**需求分析：**
1.  **核心目標**：整理混亂的 `README.md` (原始為對話紀錄)，使其結構化。
2.  **特定要求**：
    *   釐清事件進度 (Timeline)。
    *   提取判決內容 (Judgment Extraction)。
    *   判決需獨立儲存為結構化資料 (Structured Data)，以便未來程式擴充。
    *   重點關注「防水層」相關觀點。

---

## 2. AI 思考過程 (Reasoning Process)

### 第一階段：理解與規劃 (Planning)
*   **現況分析**：讀取 `README.md` 後，發現內容是大量的 LINE 對話紀錄與一篇完整的判決書。資訊雖然豐富但雜亂，難以快速掌握重點。
*   **結構設計**：
    *   *判決資料*：使用者提到「資料結構」且未來要「寫程式抓更多」，因此 `JSON` 是最佳選擇。它易於程式讀取，也能清楚定義欄位 (如 `case_id`, `summary`, `waterproofing_points`)。
    *   *文件重構*：`README.md` 不應只是對話備份，而應轉化為「專案首頁」。需要包含：
        *   **事件進度**：讓使用者一眼看出現在進行到哪 (存證信函階段)。
        *   **核心爭點**：歸納對話中的技術細節 (如素地整平、輕質灌漿牆)。
        *   **法律策略**：結合判決內容，提供行動建議。
*   **工具選擇**：
    *   使用 `task.md` 追蹤進度。
    *   使用 `implementation_plan.md` 讓使用者預覽並批准變更 (Agentic Workflow 的核心)。

### 第二階段：執行 (Execution)
1.  **建立資料 (Data Extraction)**：
    *   先創建 `judgments.json`。
    *   從 `README.md` 中複製判決全文，並人工摘要出「防水層觀點」（如：法院認證需剔除見底、需做止水墩）。這是 AI 的價值所在——不是單純複製，而是「理解並提取」。
2.  **重寫文件 (Refactoring)**：
    *   將 `README.md` 大幅改寫。
    *   使用 Markdown 的 Alert 語法 (`> [!TIP]`) 來增強可讀性。
    *   將對話轉化為「溝通策略」與「話術範本」，讓文件更具實用性。

### 第三階段：驗證與優化 (Verification & Refinement)
*   **初步驗證**：檢查 `judgments.json` 格式。
*   **使用者回饋**：使用者指出 `judgments.json` 內含全文太難閱讀，希望改存純文字檔。
*   **快速迭代**：
    *   創建 `judgments_files/` 目錄存放 `.txt` 全文。
    *   更新 `judgments.json`，將 `full_text` 欄位改為 `text_file` 路徑參照。
    *   此過程展示了 Agent 應對使用者回饋的靈活性。
*   **最終交付**：建立 `walkthrough.md` 總結所有變更。

### 第四階段：資料擴充 (Data Enrichment)
*   **需求變更**：使用者提供了 3 個新的判決連結，要求分析並加入資料庫。
*   **執行策略**：
    *   使用 Browser Tool 抓取判決全文。
    *   **深度分析**：運用使用者提供的「工程邏輯」（如：打底=剔除），從判決書中推導出支持「全室重做」的論點。
    *   **資料整合**：將新判決加入 `judgments.json`，並維持「JSON + Text File」的架構。
*   **價值**：不僅是資料蒐集，更提供了具備「觀點」的結構化數據。

### 第五階段：自動化探索 (Auto-Discovery)
*   **需求變更**：使用者提供搜尋結果頁面，要求自動處理剩餘判決。
*   **執行策略**：
    *   **批量處理**：從搜尋頁面提取所有連結，過濾重複項，分批抓取全文。
    *   **關鍵字篩選**：針對「剔除」、「打底」、「結構層」等關鍵字進行深度掃描。
    *   **證據強化**：發現如 `113年度上易字第677號` 等高價值判決，其工法明確要求「敲除至結構層」，為「全室重做」提供了終極法律依據。
*   **成果**：資料庫擴充至 15 筆判決，形成強大的法律論述基礎。

## 3. 檔案結構說明 (File Structure)

本目錄 (`training_materials/`) 包含以下檔案，展示了 Agent 的工作流：

1.  **`task.md`**：任務清單。AI 用來自我管理進度，確保不遺漏步驟。
2.  **`implementation_plan.md`**：實作計畫。在動手修改前，先寫出計畫供使用者審閱 (Plan-Execute 模式)。
3.  **`walkthrough.md`**：交付說明。任務完成後，總結做了什麼、改了什麼。
4.  **`process_documentation.md`** (本檔案)：後設認知 (Metacognition)。紀錄 AI 的思考路徑。

## 4. 關鍵學習點 (Key Takeaways for Training)

*   **結構化思維**：將非結構化文本 (聊天記錄) 轉化為結構化數據 (JSON) 與結構化文件 (Markdown Sections)。
*   **主動性 (Proactiveness)**：不只是「存檔」，而是主動分析判決中的「防水觀點」並歸納「溝通策略」。
*   **Agentic Workflow**：遵循 `Plan` -> `Approval` -> `Execute` -> `Verify` 的標準作業程序，確保產出符合預期且風險可控。
